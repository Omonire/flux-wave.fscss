# Tutorial 09 — Array-Generated Bands

The four bands are not four hand-copied blocks. They are **generated by an FSCSS array loop**. This is the single most important FSCSS idea in flux-wave, so let's slow down and take it apart.

## The tiny engine inside flux-bands

```fscss
@arr flux-i[count(4,1)]
  @use(st).wave-@arr.@use(counter)[]{
    background: var(--flux-band@arr.@use(counter)[]-bg, none);
    ...
  }
```

Three moving parts:

### 1. The drive array

```fscss
@arr flux-i[count(4,1)]
```

Declares an array literally named `flux-i` containing `1, 2, 3, 4` (from `count(4,1)` — count up from 1 to 4). This little list *drives* the whole generation.

### 2. Auto-iteration with empty brackets

```fscss
.wave-@arr.@use(counter)[]
```

The **empty brackets** `[]` are the loop. For each item in the array, FSCSS runs the block once, substituting the current item. Result selectors:

```text
.wave-1
.wave-2
.wave-3
.wave-4
```

### 3. Token name synthesis

Inside the block, the same counter-iteration is used to *build property names*:

```fscss
var(--flux-band@arr.@use(counter)[]-bg, none)
```

At iteration `n`, this becomes `var(--flux-band{n}-bg, none)` → `--flux-band1-bg`, `--flux-band2-bg`, …

## The full expansion, iteration by iteration

| Iteration | Selector | Token lookup (bg shown) |
|---|---|---|
| 1 | `.wave-1` | `--flux-band1-bg` |
| 2 | `.wave-2` | `--flux-band2-bg` |
| 3 | `.wave-3` | `--flux-band3-bg` |
| 4 | `.wave-4` | `--flux-band4-bg` |

Each also reads `top`, `height`, `opacity`, `filter`, `delay`, `duration` with the same `N` suffix — 7 tokens × 4 bands = 28 lookups entirely data-driven.

## Why this matters to you

- **Add a band = add a number**, not a block: Tutorial 12 shows replacing `count(4,1)` with, say, `count(6,1)`.
- **Rename across the board:** the class suffix (`wave-2`) and token suffix (`--flux-band2-*`) are *produced by the same iteration*, so they can never drift apart.
- **The library stays tiny:** the CSS-generating source is ~10 lines even though it emits 4 complete band rules.

## The mental model

> Arrays → iteration → selectors + token names.

When you see `[]` after an array in flux-wave source, read it as: *"repeat this block once per array item, using the item as the current index."*

## Compared to hand-writing (why not)

Hand-written version would be 700px of copy-pasted CSS. The array version is one block plus data. And when you change from 4 to 6 bands, the hand-written version becomes 2×300px of tedious edits — the array version is a single `count(6,1)`.

## Checkpoint

- `@arr flux-i[count(4,1)]` is the array that drives band generation.
- Empty brackets `[]` iterate once per array item.
- Selector suffixes and token suffixes come from the same iteration, so they always match.
